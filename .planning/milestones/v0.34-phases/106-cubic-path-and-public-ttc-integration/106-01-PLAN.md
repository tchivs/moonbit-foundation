<edge_assumptions>
1. CFF-04 empty input is resolved by typed APIs: MoonBit `GlyphId` and `ByteView` are not nullable; an admitted glyph with no drawing segments returns an empty `Path2`.
2. CFF-04 encoding is the existing cmap contract over Unicode scalar values and numeric GIDs; no normalization, code-point-string length, or grapheme layer is introduced.
3. `Path2::with_capacity(Int)` is the single new format-neutral public seam; negative capacity follows the established Array constructor failure behavior, zero is a valid empty path, and exact positive capacity preserves command order.
4. The path backing-store authority unit is 64 bytes per retained publishable command. It is conservative, internal to charging, and frozen with exact/one-short tests without changing the existing glyf 32-byte formula.
5. Rational coordinates use checked quotient-plus-remainder conversion to binary64 at `Point2` construction, rejecting any unrepresentable/non-finite result with stable CFF path-coordinate Data context.
</edge_assumptions>

| Boundary | Description |

| caller-owned OTTO/CFF bytes -> complete admission | Attacker-controlled directory, common-table, CharString, matrix, and subroutine facts must validate before opaque Font publication. |
