## Gap root cause

Plan deficiency: Plan 104-01 required exact typed Top DICT schemas but grouped `PaintType` (`12 5`, internal operator `0x105`) and `StrokeWidth` (`12 8`, internal operator `0x108`) into a generic one-operand branch. Execution followed that instruction, so valid values were accepted without being retained or constrained. This plan corrects the schema boundary itself rather than adding a downstream check.

## Closed profile decision

- The supported fill-outline profile has `PaintType = 0`. Omission uses the CFF1 default; every successfully decoded `CffNumber` with `magnitude == 0` is accepted, including integer zero and exact-real zero. The existing number decoder normalizes a signed real zero to non-negative zero, but the semantic predicate is value-based rather than encoding-based.
- `PaintType = 2`, exact real `2.0`, negative values, fractional values, and every other well-formed non-zero `CffNumber` are recognized but unsupported and return a stable capability/profile error before admission can publish facts. PaintType does not use `cff_number_nonnegative_integer`, because that would misclassify well-formed non-integer or negative numbers as malformed data.
- `StrokeWidth` is semantically relevant only to stroked outlines. Its supported domain is likewise omission or any successfully decoded exact-zero `CffNumber`; every well-formed positive, negative, integer, or exact-real/fractional non-zero value returns a stable capability/profile error.
- Because every accepted value collapses to the same closed default semantics, the reducer validates these operators but does not add redundant retained fields to `CffTopDict`. Seen flags remain local to enforce singleton duplication.

## Executable error and precedence contract

- Parser-level errors keep the contexts produced by the existing single DICT parser: an operator with no operands is Data at `font-cff-top-dict-arity`; a reserved operator byte is Data at `font-cff-top-dict-reserved`; trailing operands without an operator are Data at `font-cff-top-dict-truncated`; a truncated escaped operator uses `font-cff-top-dict-operator`; truncated integer windows retain the base `font-cff-top-dict` window context; malformed real encodings retain `font-cff-top-dict-real`, `font-cff-top-dict-real-reserved`, `font-cff-top-dict-real-padding`, or `font-cff-top-dict-real-range` as applicable.
- A completed PaintType/StrokeWidth entry reaches the typed reducer. Two or more operands are Data at `font-cff-top-paint-type-arity` or `font-cff-top-stroke-width-arity`; a repeated supported-zero singleton is Data at `font-cff-top-paint-type-duplicate` or `font-cff-top-stroke-width-duplicate`; a well-formed non-zero operand is Capability at `font-cff-paint-type-unsupported` or `font-cff-stroke-width-unsupported`.
- Encounter order is deterministic. The parser invokes Top typed reduction immediately after each complete operator. An unsupported PaintType/StrokeWidth therefore returns Capability without parsing a later reserved/truncated suffix. A preceding self-terminating reserved operator or malformed real returns its existing Data outcome because no capability has yet been recognized; end-of-input truncation is not used as a preceding reverse-order fixture.
