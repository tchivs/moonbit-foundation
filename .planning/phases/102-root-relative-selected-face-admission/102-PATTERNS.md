**Checked root subview pattern** (`directory.mbt:299-314`):

fn checked_font_table_view(

  offset : UInt64,
  length : UInt64,

Copy unchanged for selected tables. This is the no-copy/root-revision mechanism. Avoid taking a directory subview and then interpreting table-record offsets against it.

Replace the standalone predicate `table_offset < directory_end` (`directory.mbt:541`) with a half-open overlap test against `[directory_start, directory_end)` so non-empty tables before the selected directory remain legal.

**Existing incremental authority pattern** (`tables.mbt:918-958`):

```moonbit
fn font_preflight_admission_work(
  budget : @budget.Budget,
  max_work : UInt64,
  work : UInt64,
) -> Result[Unit, @error.CoreError] {
  if work > max_work {
    return Err(font_limit_error("max-work", work, max_work))
  }
  budget.preflight(@budget.ResourceCharge::new(..., work~))
}

fn font_charge_admission_work(
  budget : @budget.Budget,
  work : UInt64,
) -> Result[Unit, @error.CoreError] {
  budget.charge(@budget.ResourceCharge::new(..., work~))
}
```

Copy this split into a private dual-mode ledger:

- standalone mode preflights and charges at the exact existing sites;
- collection mode checked-adds each stage to virtual staged work, cumulatively preflights the real caller budget, and does not charge;
- both modes retain `max_work` checks before attacker-declared loops.

Do not replace the caller budget with `Budget::new(budget.remaining())`; that loses live ancestor authority.

## Shared Patterns

### Checked arithmetic before attacker-controlled loops

Every offset/count formula uses `@checked.checked_add`, `checked_mul`, `CheckedRange`, and explicit resource remapping before traversal. Apply this to `directory_start + 12 + 16*i`, `D + T`, pair counts, selected extent sums, and cumulative staged work.

### Stable error taxonomy

- collection facade gates: `font-collection-open-face`;
- retained-root drift: `State/InvalidRange`;
- index: `InvalidInput/InvalidRange`;
- unsupported cached profile: `Capability/CapabilityUnavailable`;
- deep selected directory/table errors: retain existing `font-*` contexts and wire order;
- limits/budget: existing `Resource/BudgetExceeded`.

Avoid new collection-prefixed duplicates for deep parser failures.

### Revision-first and revision-last

Public operations call `require_revision` before validating other input. Work that reads retained mutable bytes performs a second guard immediately before charge/publication. Returned selected fonts inherit the original collection opening revision, so mutate-then-restore remains invalid.

### Atomic collection transaction, historical standalone transaction

Collection selection may perform cumulative real-budget preflights but commits exactly once after semantics and the final revision guard. Standalone `Font::open` retains its existing staged commits and final remainder charge. This distinction is the central dual-mode contract.

### Public behavior equivalence

Compare standalone and selected fonts only through existing public methods:

- `units_per_em`, global bounds, both line metrics;
- `glyph_for_scalar`, `glyph_id`, horizontal metrics;
- kerning hit and miss;
- outline command/value equivalence under equal outline budgets.

Do not compare private `DirectoryFacts` as the black-box oracle.

### Threat-test conventions

1. Make the incorrect implementation stay in bounds so a mere range check cannot pass the test.
2. Combine two faults to lock precedence.
3. Assert category, code, operation, context, requested, and limit where defined.
4. Snapshot all budget dimensions before a failing call and prove they are unchanged.
5. Use deterministic callback hooks for mid-operation mutation instead of timing.
6. Test exact fit and one-short for each independently authoritative dimension.

## Copy / Adapt / Avoid Summary

| Area | Copy | Adapt | Avoid |
|---|---|---|---|
| Directory | `TableWindow`, root `checked_font_table_view`, existing deep errors | directory-field base and half-open directory overlap | adding base to record table offsets; synthetic standalone copy |
| Checksums | table checksum loop and `head` zeroing | explicit standalone/collection dispatcher | disabling checksums; whole-root check in collection mode |
| Ledger | current preflight-before-loop order | private standalone-incremental vs collection-deferred policy | detached shadow budget; real collection charges before publication |
| Font construction | exact existing `Font` fields/object literal | accept inherited opening revision and mode-specific plan | `CollectionFace`, provenance fields, duplicate semantic readers |
| Collection facade | revision/index gate and private test-hook wrapper | cached profile gate and selected admission call | sibling rescan, face cache, consuming selection |
| Tests | generated bytes, wrong-rebase, exact/one-short, mutate/restore | real selected static face and public equivalence | production-parser-derived expected values; broad Phase 103 fixture work |
| Policy | exact ordered allowlist and independent negatives | one method, 84→85, Phase 102 naming | additional public types/imports/dependencies; committing generated mbti |

## No Analog Found

No planned responsibility lacks a close analog. The only genuinely new behavior is the private dual-mode commit policy, but its two halves already exist as:

- incremental `preflight`/`charge` calls in cmap/kern admission; and
- deferred final guard then one charge in `FontCollection::open`.

The implementation should compose those patterns rather than invent a new subsystem.
