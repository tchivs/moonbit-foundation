# Phase 100: Portable Font Qualification - Context

**Gathered:** 2026-07-27
**Status:** Ready for planning

<domain>
## Phase Boundary

Qualify the already-published `tchivs/mb-font/font` contract without expanding its feature boundary. This phase supplies one reproducible public immutable-bytes workflow, a generated hostile-input matrix, one licensed real-font specimen with independently checked facts, and canonical four-target/dependency evidence. New font formats, shaping, hinting, rasterization, host font discovery, GUI state, FFI, and convenience API expansion remain outside the phase.

</domain>

<decisions>
## Implementation Decisions

### Licensed Real-Font Specimen
- **D-01:** Use the complete DejaVu Sans 2.37 `DejaVuSans.ttf` selected by the v0.32 stack research. The official single-font archive is 417,746 bytes with published and independently rechecked SHA-256 `5c6e497a2f36552cb5ffb112c413a6af39c0f3c47653662b90b4fa6499822fd7`; its extracted font is 757,076 bytes with SHA-256 `7da195a74c55bef988d0d48f9508bd5d849425c1770dba5d7bfc6ce9ed848954`. Planning must re-fetch and verify both identities before repository intake. — **Reversibility:** costly — replacing the specimen changes redistributed bytes, provenance, generated test source, table inventory, and all frozen interoperability facts.
- **D-02:** Commit the exact upstream font bytes and the applicable upstream license/notice under a dedicated `fixtures/font/` subtree. Add an `external` manifest record with the official immutable release source, author, retrieval date, exact digest, precise DejaVu/Bitstream license identifier, `confirmed` redistribution, and the Phase 100 expected use. Do not rely on an installed font or an unpinned download.
- **D-03:** Record a machine-readable table inventory and semantic fact set derived independently of `mb-font`. The intake/generation path must identify its oracle and version or implement a small separately audited parser; `mb-font` output cannot certify itself.
- **D-04:** Use the real specimen for representative format-4/12 mapping, named metrics, simple/composite outlines, and legacy `kern` interoperability. A separate compact generated workflow fixture still owns the minimal nonzero format-0 kerning and exact simple/composite command oracle so real-font complexity does not obscure a failing branch.

### Fixture Transport and Reproducibility
- **D-05:** Keep canonical fixture identity in `fixtures/font/`; portable MoonBit tests must consume an exact compile-time representation generated from those bytes, never ambient filesystem APIs. Prefer a supported compile-time byte embedding primitive if research confirms one across all four targets; otherwise generate deterministic bounded byte chunks and verify round-trip length plus SHA-256 binding in the generator/quality gate.
- **D-06:** Add one deterministic fixture generator/intake script that is idempotent, refuses upstream digest or license drift, preserves manifest ordering, and emits all generated MoonBit/vector artifacts from canonical inputs. Generated artifacts must carry a “do not edit” header and be reproducible byte-for-byte.
- **D-07:** Generated hostile cases are project-authored Apache-2.0 fixtures. External font bytes remain under their upstream license; do not relabel external bytes, derived byte copies, or notices as project-generated.

### Public Workflow and Semantic Oracle
- **D-08:** Freeze one black-box public workflow over immutable generated bytes: construct explicit `FontLimits` and budgets, `Font::open`, map chosen BMP and supplementary scalars, inspect named global/per-glyph metrics, extract one simple and one composite `Path2`, and query a nonzero kerning pair. Assert stable semantic facts and command sequences, not timing, debug formatting, allocation addresses, or target representations.
- **D-09:** Add a second public real-font interoperability scenario that opens DejaVu Sans, verifies selected Unicode mapping/metrics/simple-and-composite outline facts, and verifies an independently curated legacy kerning fact. Documentation must show how both scenarios relate; the compact generated workflow is the minimal complete feature oracle, while the real font is the representative interoperability oracle.
- **D-10:** Produce one canonical evidence record per target with the same closed schema and compare normalized semantic payloads byte-for-byte. Evidence includes source/fixture digests, toolchain identity, target, commands, public facts, hostile outcome IDs, dependency facts, and pass status.

### Hostile-Input Qualification
- **D-11:** Define a closed declarative generated matrix covering at least malformed data, recognized unsupported capability, retained-source mutation drift, checked arithmetic/range failure, semantic limit exhaustion, and authoritative budget exhaustion. Each case freezes public `ErrorCategory`, `ErrorCode`, relevant stable context/limit fields, and the operation stage; rendered prose is not an oracle.
- **D-12:** Every hostile case runs through public entry points on `js`, `wasm`, `wasm-gc`, and `native`. Target-specific expected results, skipped targets, and “native-only” allowances are forbidden.
- **D-13:** Preserve transactional expectations: failed open never publishes a `Font`; failed outline never publishes partial geometry; exact-fit/one-short budget and limit pairs remain explicit qualification facts.

### Qualification Gates and Scope Control
- **D-14:** Add a dedicated font qualification selector that runs isolated `mb-font` checks/tests on all four targets, compares canonical evidence, validates fixture provenance/digests/generation drift, checks the exact public interface and manifest description, and proves the `mb-font -> mb-core` dependency edge.
- **D-15:** Run the repository-wide policy/Required lane separately so unrelated workspace behavior cannot be mistaken for font evidence. The known Windows unscoped `mb-image/png` driver stall must be reported honestly if reproduced, but must not weaken or suppress the isolated Phase 100 gates.
- **D-16:** Enforce negative boundary assertions for FFI/native stubs, filesystem or host font discovery, GUI state, canvas/image/color dependencies, shaping, hinting execution, CFF/CFF2, and rasterization. Qualification tooling may inspect bytes offline; production and portable test behavior may not acquire host capabilities.
- **D-17:** This is qualification-first work. Do not add public convenience APIs or broaden supported font profiles. Production changes are allowed only for a concrete standards/conformance defect exposed by the chosen fixture or hostile matrix, and must receive focused regression tests plus interface review.

### the agent's Discretion
- Exact file names, evidence JSON field names, generator implementation language, and test source chunk size are flexible if all locked identity, reproducibility, portability, and no-self-oracle requirements hold.
- The planner may choose the exact Unicode scalars/glyphs from DejaVu Sans after independently proving which one is simple and which one is composite.
- The planner may split the generated public workflow and hostile matrix across test files for compiler/runtime practicality, while retaining one canonical workflow ID and one closed outcome matrix.

</decisions>

## Existing Code Insights

### Reusable Assets
- The Phase 97-99 public test builders already create checksum-correct fonts with cmap, metrics, simple/composite glyf data, and legacy kern pairs; they can seed the compact complete workflow and hostile cases.
- `Font::open`, `glyph_for_scalar`, `horizontal_metrics`, `outline`, and `kerning` already expose the entire required workflow with source revision guards and structured errors.
- Existing fixture manifest and policy functions already validate required fields, exact SHA-256, repository containment, external confirmed redistribution, and canonical field sets.
- Existing four-target quality selectors, interface baselines, documentation checks, and policy allowlists provide patterns for a focused font qualification selector.

### Established Patterns
- Portable tests mirror canonical repository fixtures into generated MoonBit source when target runtimes cannot load repository JSON or binary files.
- Generated fixtures have checked-in canonical source data, deterministic generators, “do not edit” outputs, and drift gates.
- Public black-box tests assert stable semantic facts; white-box tests cover parser and representation invariants.
- Qualification evidence distinguishes focused package success from unrelated workspace-wide blockers and records exact commands/toolchain/HEAD.

### Integration Points
- Add a `fixtures/font/` subtree and append manifest records without reordering existing entries.
- Extend `modules/mb-font/font` tests and `modules/mb-font/README.mbt.md` without changing production dependencies.
- Add font-specific fixture generation and quality selection under `scripts/fixtures/` and `scripts/quality/`, then wire it into `scripts/quality.ps1` and CI evidence.
- Update module/root documentation, changelog, policy inventory, and Phase 100 coverage/verification artifacts.

</code_context>

<specifics>
## Specific Ideas

- The rechecked DejaVu Sans specimen has 20 tables: `FFTM`, `GDEF`, `GPOS`, `GSUB`, `MATH`, `OS/2`, `cmap`, `cvt `, `fpgm`, `gasp`, `glyf`, `head`, `hhea`, `hmtx`, `kern`, `loca`, `maxp`, `name`, `post`, and `prep`. The official archive also contains the full 8,816-byte license notice.
- Keep the real-font evidence readable: record byte length, SHA-256, sorted table inventory with offsets/lengths/checksums, selected scalar-to-glyph facts, named metrics, path command fingerprints, and neutral kerning result.
- Make the dedicated qualification command suitable for local maintainers and CI, with deterministic artifact paths and no GUI or network requirement after fixture intake.

</specifics>

<deferred>
## Deferred Ideas

- Additional font families or a larger interoperability corpus belong to a later compatibility expansion.
- TTC/OTC, WOFF/WOFF2, CFF/CFF2, variable and color fonts, nested composites, phantom attachment, hinting, shaping/GPOS, discovery/registry, rasterization, and authoring remain future requirements.
- Publication or stability promotion beyond the existing candidate policy belongs to milestone/release governance, not this qualification phase.

</deferred>
