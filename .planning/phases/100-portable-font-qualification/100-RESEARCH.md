## Summary

Phase 100 should be implemented as a qualification layer around the existing public `Font` contract, not as a new font feature. The canonical external input is the exact DejaVu Sans 2.37 single-font release; the canonical portable test input should be generated MoonBit `Bytes` literals because the pinned MoonBit documentation and package configuration expose byte/bytes literals but no documented cross-target compile-time file-inclusion primitive. [CITED: https://docs.moonbitlang.com/en/latest/language/fundamentals.html] [VERIFIED: pinned toolchain/package schema inspection]

The real font immediately exposes one concrete compatibility defect: its `cmap` contains four supported Unicode format-4/12 records plus a valid Macintosh format-6 record, while both `font_cmap_declared_work` and `font_admit_cmap_lookup` currently parse every encoding record through a format-4/12-only decoder. Opening the specimen therefore reaches `font-cmap-envelope` before the selected format-12 map can be retained. Fix this narrowly by bounding and ignoring non-selected, recognized cmap formats while continuing to fully validate every candidate format-4/12 subtable; add the real-font regression and a compact format-6 coexistence regression without exposing format 6 publicly. [VERIFIED: `modules/mb-font/font/tables.mbt`, `cmap.mbt`, and independently parsed DejaVu bytes]

**Primary recommendation:** Intake DejaVu once through a fail-closed PowerShell generator/oracle, generate deterministic 4 KiB MoonBit byte-literal chunks plus closed JSON facts, repair only the cmap coexistence defect, then qualify identical normalized semantics and hostile outcomes on four isolated targets before running the repository Required lane. [VERIFIED: repository generator and quality patterns] [ASSUMED]

### Pattern 1: One-way canonical generation

Canonical TTF/license/hostile JSON inputs generate MoonBit source; generated MoonBit output never updates the oracle. `-Check` regenerates into memory or a temporary file and compares exact UTF-8-without-BOM bytes. [VERIFIED: existing fixture generator conventions]

Generate 4,096-byte `Bytes` literal chunks, join them deterministically in one helper, and place source length plus SHA-256 in the generated header. The generator must reconstruct the emitted literal bytes and verify exact length/hash before write. [CITED: https://docs.moonbitlang.com/en/latest/language/fundamentals.html] [ASSUMED]

### Pattern 2: Closed independent oracle

The PowerShell oracle parses only the fields required by the frozen schema: SFNT directory/checksums, `head`, `hhea`, `maxp`, `OS/2`, `hmtx`, `cmap` formats 4/12, `loca`/selected `glyf` records, and `kern` v0 format 0. Keep it in the generator, not `modules/mb-font`; unit-check the oracle against exact offsets above and fail on unknown schema keys. [CITED: https://learn.microsoft.com/en-us/typography/opentype/spec/otff] [CITED: https://learn.microsoft.com/en-us/typography/opentype/spec/cmap] [CITED: https://learn.microsoft.com/en-us/typography/opentype/spec/glyf] [CITED: https://learn.microsoft.com/en-us/typography/opentype/spec/kern]

### Pattern 3: Semantic evidence, not runner output

Each target record should use the same sorted closed schema:


## Concrete Compatibility Defect

### Valid format-6 cmap coexistence is rejected

`font_cmap_subtable_facts` returns `font-cmap-envelope` for any format other than 4 or 12. Both admission-work discovery and lookup admission call it for every encoding record before deciding whether the record is a canonical supported mapping. DejaVu contains a platform-1 format-6 mapping alongside its canonical format-4/12 records, so the real font cannot currently open. [VERIFIED: local source plus independent DejaVu inventory]

The focused repair should:

1. Read enough of each encoding record/subtable header to establish a checked, in-table length for recognized non-selected formats. [CITED: https://learn.microsoft.com/en-us/typography/opentype/spec/cmap]
2. Fully validate and charge only supported format-4/12 candidates; ignore bounded format 6 for selection. [VERIFIED: existing public scope]
3. Continue rejecting malformed offsets/lengths and duplicate canonical supported record keys. [VERIFIED: existing contract]
4. Add a compact regression containing format 6 plus canonical format 12 and the full DejaVu open regression. [VERIFIED: defect trigger]
5. Regenerate/diff the public interface and prove it is unchanged. [VERIFIED: CONTEXT D-17]

Other likely pressure points are limits, not defects: the real font needs `max_source_bytes>=757076`, `max_table_bytes>=556004`, `max_glyphs>=6253`, `max_name_records>=26`, `max_cmap_records>=5`, `max_kern_pairs>=2727`, `max_outline_instruction_bytes>=534`, and `max_post_name_bytes>=49512`. Use explicit comfortable ceilings in the happy workflow and exact-fit/one-short values only in dedicated limit tests. [VERIFIED: independent DejaVu facts and `FontLimits` source]

2. **Compatibility regression:** prove the format-6 coexistence failure red, implement the narrow cmap repair, run focused compact and DejaVu tests, and confirm no public interface change.
3. **Public qualification/evidence:** freeze compact exact commands, DejaVu semantic facts, hostile outcome records, four target evidence, and normalized comparison.
4. **Policy/docs/CI closure:** wire focused selector and CI artifact upload, update README/changelog/policy inventory, run isolated qualification then the separate Required lane.

This ordering keeps expensive generated-source churn ahead of semantic test authoring and isolates the only expected production repair before evidence is frozen. [VERIFIED: dependency analysis]

## Common Pitfalls

### Treating every cmap record as supported
**What goes wrong:** DejaVu fails admission on its valid Macintosh format-6 record. [VERIFIED: source/specimen audit]  
**Avoid:** classify/bound unsupported records before supported-subtable decoding; select only canonical 4/12 candidates. [CITED: https://learn.microsoft.com/en-us/typography/opentype/spec/cmap]

### Claiming format-4 public execution when format 12 wins
**What goes wrong:** the test description overstates which lookup branch was used. [VERIFIED: cmap priority]  
**Avoid:** use the compact workflow to exercise format 4; describe DejaVu format 4 as admitted/inventoried and its public BMP lookup as format 12.

### Re-labeling generated font literals as Apache-2.0
**What goes wrong:** derived external bytes lose upstream provenance. [VERIFIED: CONTEXT D-07]  
**Avoid:** generated header names canonical TTF path/hash/license; only hostile project-authored vectors are Apache-2.0.

### Evidence normalization hides divergence
**What goes wrong:** a missing fact or skip is removed as “target noise.” [VERIFIED: CONTEXT D-10/D-12]  
**Avoid:** remove only target/command runner metadata and byte-compare the complete semantic payload.

### Compiler/source-size instability
**What goes wrong:** one enormous literal or array expression becomes slow or exceeds a backend/compiler limit. [ASSUMED]  
**Avoid:** deterministic bounded chunk functions, a Wave-1 four-target compile probe, and generator-owned chunk size.

### Oversized real-font limits obscure limit semantics
**What goes wrong:** happy-path ceilings are copied into hostile exact-fit tests or declared maxp values are mistaken for caller limits. [VERIFIED: Phase 99 taxonomy]  
**Avoid:** separate named happy-path limits from exact/one-short case factories.
