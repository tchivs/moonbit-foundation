# v0.31 Milestone Audit — SVG Numeric Boundary Unification

## Verdict: GAPS FOUND

Phase records and their four-target test evidence are complete, but the phases do
not fully wire the checked geometry seam into lowering.  A public manually
constructed `Group` with an unsafe affine reaches a `DrawingList` as a raw
`PushTransform`.  This is an integration blocker: the Phase 95 production seam
and Phase 96 qualification controls meet at an acknowledged bypass rather than a
single checked boundary.

## Scope and evidence read

- Milestone scope: Phases 95–96 in [ROADMAP.md](ROADMAP.md), with
  `SVGUNI-01` assigned to Phase 95 and `SVGUNI-02`/`SVGUNI-03` to Phase 96 in
  [REQUIREMENTS.md](REQUIREMENTS.md).
- Phase records: both CONTEXT files, all four plans, all four summary frontmatter
  records, and both verification reports.  Both reports say `passed` at 7/7
  must-haves; summary frontmatter respectively claims `SVGUNI-01`,
  `SVGUNI-02`, and (for 96-02) qualification work.
- Live qualification: `moon test modules/mb-svg/svg --target all --frozen` run
  during this audit: **137/137 passed** on each of `wasm`, `wasm-gc`, `js`, and
  `native`.
- Actual implementation/test trace: `geometry.mbt`, `scene.mbt`, `lower.mbt`,
  `svg_test.mbt`, `geometry_wbtest.mbt`, `lower_wbtest.mbt`, and
  `portable_qualification_wbtest.mbt`.

The distinction demanded by the phase context is otherwise real and correctly
tested:

- Parser-originated invalid SVG is fail-closed.  `parse_svg` returns `Err` before
  a `SceneNode` is returned; `svg_test.mbt:162-192` covers derived root,
  affine, primitive, point-list, CanvasPath, and path-point failures.
- Manual invalid roots and leaf/path nodes use the deliberately total lowerer:
  `lower.mbt:94-128` chooses identity or an empty `Path2`; the repeated-output
  controls in `lower_wbtest.mbt:764-823,838-861` exercise that behavior.
- Manual invalid **Group** values do neither.  The direct seam check at
  `lower_wbtest.mbt:825-829` gets `svg-numeric-derived`, but the next call at
  `:832-835` expects a `PushTransform` whose `tx` is `65537`.  This is an
  observable unsafe drawing-list publication, not an empty-path/identity total
  fallback and not a parser `Err`.

## Required closure

1. Route `lower_node`'s `Group` transform through a private total adapter built
   on `checked_compose_affine` (or equivalent shared checked affine fact), using
   deterministic identity recovery for an invalid manually constructed Group.
   Keep parser-originated failures as `Err(CoreError)`; do not turn them into
   DrawingLists or add a public `Result` API.
2. Replace the current `PushTransform(65537)` differential expectation with
   identity-fallback semantics, then rerun the frozen all-target package gate.
3. In a separate cleanup, remove the proven-unused legacy helper blocks in
   `scene.mbt` and `lower.mbt`.  They are maintenance debt, not the present
   runtime bypass.

No production code, roadmap, state, or user-owned untracked files were changed
by this audit.
